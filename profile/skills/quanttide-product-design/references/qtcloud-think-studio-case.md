# 案例：qtcloud-think studio 设计迭代（2026-08-22）

完整演进记录，展示五条纪律如何被逐一触发纠正。

## 第一轮：转译概念（被否）

AI 设计：导航 = 收集/澄清/结构（把 4D 认知过程转译为"用户语言"）

用户纠正：**"为什么不直接用原始概念"** → 导航改为 4D 本身：感知/理解/预测/决策。

## 第二轮：第四环选词

用户问："决策和行动用哪个比较好"

判断：**决策**（认知闭环终点；行动是现实执行，已出认知圈）。用户认可。

## 第三轮：任务名（被纠正）

AI 写的任务：清晰度判断/澄清对话/结构化加工/本体挂接/模式升级/目标确立/决策记录

用户纠正：**"任务都应该是动作"** → 判断清晰度/澄清想法/加工结构化/挂接本体/升级模式/确立目标/记录决策。

## 第四轮：预测任务（被纠正）

AI 写：挂接本体 + 升级模式（结构组织类）

用户纠正：**"预测的任务不太对"** → 预测是推演（从现状推未来），不是结构组织。改为：识别模式（AI 识别反复模式）+ 推演走向（趋势/分支）。

## 第五轮：对照本体（被问倒 → 砍）

AI 写：对照本体（推演与心智模型本体校验一致/冲突）

用户问：**"对照本体是什么"** → AI 说不清操作方式 → 用户："移除"。

## 第六轮：残留本体（同步砍）

studio scope 里"两层建模落地：本体树呈现/实例挂接/模式升级"——需求地图已移除本体任务 → 同步移除（需求地图是法源）。

## 第七轮：四审修正

1. 决策页"与本体关联"残留 → 砍（只留实例关联）
2. "升级为情境意识实例"独立动作说不清 → 加工完成即形成（自动）
3. "导入素材"来源不明 → 明确为 quanttide journal
4. "确立目标"无交互 → 从推演走向中选择（AI 候选 + 用户确认）

## 第八轮：验证先行

用户问："**我们要怎么才能验证规划的这些功能值得做呢**"

方法（被认可）：
- 最小闭环先行（只做感知+理解，一周真实用起来）
- 真实使用检验（主动用/缺了难受 = 值得做）
- 砍掉验证（砍了不受影响 = 不值得做）
- 数据驱动（使用频率砍死功能）
- 预测/决策页延迟（无实例数据就是空壳）

## 规律

- 每次被纠正的都是"AI 发明的层"（转译词、结构组织任务、含糊校验概念、无交互动作）
- 留下的都是"领域模型里真实存在"的东西（4D 过程、情境意识实例、动作）
- 用户用问题纠正（"是什么"/"为什么"），AI 必须诚实承认说不清，主动移除

## 第九轮：需求地图与 studio scope 双向同步

requirement.md（profile）与 studio scope（roadmap）修正必须**同步落地**：任务动作化、预测推演化、实例自动形成、移除本体关联——四个文件的修改同时提交（profile + roadmap 双仓库链）。

## 第十轮：设计文档三层体系

用户要求设计文档按模块分解：ROADMAP（做什么）→ doc/index.md（模块设计+实施分解）→ doc/screens/ 每页一档 + doc/{models,services,domain} 模块档。每个文档：定位 → 设计/接口 → 数据 → 验收。

## 第十一轮：DDD 分层（被纠正）

用户：**"data/不应该存在"**、"仓储指的是领域驱动的仓储" → lib 用 domain/（模型+仓储接口）+ infrastructure/（实现），不用 data/ 模糊名；仓储=Repository 接口/实现分离。种子（assets/data）与仓储无关。
