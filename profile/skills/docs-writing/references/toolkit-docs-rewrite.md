# toolkit docs/index.md 三轮重写实录（2026-09-26）

对象：quanttide-founder-toolkit 的 `docs/index.md`（多包仓库的根文档）。

## 第一轮：架构罗列（被纠正）

初稿按代码结构展开：功能定位 → 三层管线 → 解析规则 → 提取器 → 各语言包 → 共同结构。用户要求「从开发者视角切换到读者视角，读读有什么理解困难」后自查出：

1. 开头跳进术语（「第二大脑」「读懂层」「四层结构」——读者不知道是什么）
2. 没有「进 → 出」的例子（全文抽象描述）
3. 核心论点（两个仓库同一套组织方式）被放在最后当附录
4. 「异构 Markdown 文档集合」是行话
5. 「LLM 按规则填表」是隐喻，没说填什么表

随后用户追问「整体叙事逻辑有什么缺点」——根因：**按架构顺序写，不按读者问题顺序写**；且一篇干了三件事（README+设计文档+API 参考）。

## 第二轮：读者叙事（概念被纠）

改成 问题 → 洞察 → 解法 → 普遍性（验证）→ 落地。用户接着说「同构」「三层管线」等自造口语化概念不要——改「同一套组织方式」「分三步」。

## 第三轮：本质收口（定位句连改三版）

「一句话给目标读者介绍」：
- v1「把 Markdown 文档仓库变成 AI 能理解的结构化数据」→「还不够本质」（手段）
- v2「人用目录和文件名表达结构，工具让 AI 照着约定去理解」→「这个依然是手段」
- v3 触发用户给底牌：「我们的目标是搭建一套人机交互框架，能够读写共同的结构只是基础。还需要计算。」
- 定稿「人和 AI 在同一套知识结构上读写，还能在上面计算」，并把「从读写到计算」写成独立一节

**教训**：定位句拿不准时，问「这个东西为什么存在」而不是复述「它怎么工作」；用户说出「目标是 X，Y 只是基础」时，X 就是定位句的主语。

## 另一条：多包仓库的文档分层

用户纠正「3 写到 packages/dart/doc/index.md，不要搞错了」后我犯了两个错：把内容同时留在两处（重复），且超范围搬了三节（只要了一节）。用户给出划分原则：**toolkit 的 docs 记通用逻辑，各 package 的文档记录特定逻辑**。最终：
- 根 `docs/index.md`：定位、机制、为什么这么设计（所有包共用）
- `packages/dart/doc/index.md`：目录结构、类职责、开发命令（本包特定）
