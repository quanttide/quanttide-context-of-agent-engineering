# quanttide-founder 实验室设计笔记（2026-08-30 实证学习；同日追加创作谈引擎规格与产品运营评审）

仓库：`~/repos/quanttide-founder/examples/default`（独立于 quanttide 主仓库群，~/repos 平级——主仓库群只挂 quanttide-tech，founder 是个人第二大脑的平级仓库）

## 定位

"量潮创始人实验室——将方法论翻译为可执行程序的实验场"。把人先示范的方法论 diff 考古成规格，再翻译为可执行程序（LLM 提示词工具）。

## 三层架构

| 层 | 位置 | 性质 |
|----|------|------|
| 规格 | `docs/` | 待翻译为代码的方法论。每篇描述明确的输入输出与处理规则，是实现的依据 |
| 数据 | `data/` | 程序的输入与运行数据。按主题分组（fiction / agent / work），结构化是演进方向 |
| 实现 | `src/` | 代码。以 `docs/` 为规格实现，以 `data/` 为输入运行验证 |

AGENTS.md 工作原则：docs/ 每篇视为待实现规格（新增/修改时同步评估代码影响）；实现功能以对应 docs/ 篇目为**验收标准**，不跳步、不臆造规格。

## 实例一：revision（前言精修助手，已完成）

- 规格 `docs/fiction/fiction-revision.md`：七条精修原则，全部从 2026-08-15《0_前言.md》两轮人工精修 diff 归纳——**标【两轮】= 两次独立出现的确认模式**（如"弱化断言：'其实/就是'→'我渐渐发现'"）。反例也入规格："作者保留判断权：以上为倾向性准则不是硬规则（如公司维度内容作者曾一度保留，最终仍删）"
- 实现 `src/revision.rs`（35 行）：SYSTEM_PROMPT = 七条原则 + 输出要求（逐条列建议 `[规则N] 原文片段 → 建议 + 理由`、删除后检查上下文衔接、没有命中不强造建议）；doc comment 首行标规格路径
- **AI 角色限定**：程序只产出建议，终审归作者（doc comment 与规格双重声明）
- CLI：`lab revision <文件路径>`（`-` 读 stdin）；GUI：`lab-gui`（eframe/egui 粘贴评估，线程 + mpsc 防阻塞）

## 实例二：fiction-adaptation（素材→正文转化，规格已就绪排期实现）

`docs/fiction/fiction-adaptation.md`：8 条转化规律，从"同章节脚本版 vs 成稿版"diff 对比归纳（核心认知：脚本写"作者想说的道理"，成稿写"角色演出来的情绪"——从直述到演出；删除率 70-80%；独白→问答是最核心转化）。

## 实例三：创作谈引擎（creation-talk-engine，v1 已实现 → 2026-09-05 方向被否、实验中止）

`docs/fiction/creation-talk-engine.md`——用户思路一句话："**规则是可以变化的，提炼规则的程序是不变的**"。演进：规格 107 行砍到 23 行 → 正反规则都收 + 母题/风格两维度 → **用户终判"方向完全偏离了。输出结果是一个分析器而不是一个完整的创作谈"**（分点罗列/"证据："标签/母题风格编号分层/元评论=分析器文体，用户要的是一篇完整的文章）。

**当前挂起状态（2026-09-05）**：AI 按随笔体（第一人称"我渐渐发现"、瞬间为骨骼、禁列表/标签/元评论/格言总结）重写规格与 SYSTEM_PROMPT，**未提交未实测**；实测运行被用户叫停"**停下来。我们要先明确创作谈是什么**"。"创作谈=完整文章非分析报告"是 AI 提议、**未经用户确认的定义**——创作谈的定义由用户给出，等定义再动引擎，不要恢复文体实验。

**自举三实例（方法仍有效）**：

1. **规格自审**：把引擎自己的规格喂给 revision 评估器——正确判定"CLI 工具规格非叙事前言，无命中不强造"，识别三处接近命中但语境不同（规格断言≠叙事格言）。评估器判定边界清晰
2. **产物当素材**：把引擎产物当素材喂回提炼引擎 → 合并创作谈。**元认知正确是最大亮点**：识别输入全是产品非原始日志（"证据链经转引抵达日志"）、维持不足判定并给出反驳自己的分析、主动提出"提供原始日志可完整重扫"。**流水线回路：产物可当下一轮素材，体系能吃自己的输出**
3. **精修闭环——未跑通**：长文（11KB）调 revision 持续挂起（180/300/590s 三次），API 直连通——**lab 对长文调用无超时控制/流式缺失（工程缺陷待修：加 --timeout）**。教训：长文评估用 background 跑或分块，别前台连试三次烧 20 分钟

**临时文件规矩（2026-09-05 用户指令，已写入实验室 AGENTS.md）**：实验产生的 /tmp 产物必须整理进 `data/{主题}/{日期}-{描述}.md` 提交（实证：4 篇引擎产物归档 data/creation-talk/），不留仓库外孤儿文件；提交前检查 /tmp 先归档再提交。

## 产品运营评审框架（2026-08-30 revision 评审实证，可复用）

用户要求"从产品运营的角度评论" revision 时的评审框架：

1. **定位准确**：区分"验证器/PoC"与"可运营产品"——单次评估器（贴文本→收建议→完）对唯一作者用户成立，但不构成产品
2. **按用户旅程找缺失**：① 作品语境（用户要"帮我改前言"，不是"评估一段匿名文本"——缺文件级闭环：选文件→评估→采纳/拒绝逐条建议→写回文件）② 采纳界面（"终审归作者"要有行使判断权的界面，否则落在复制粘贴上）③ 状态与记忆（多轮精修无状态=重复贴文本+方法论无法通过使用数据进化）④ diff 对照（输出形态要支持产生新 diff——方法论下一次迭代的原料，fiction-revision 本身就是 diff 考古产物但程序不产生 diff）⑤ 成本透明（401 裸抛、key 配置引导、单次成本告知——用户不知道成本就不敢用）⑥ 分发形态（42MB CLI/229MB GUI 不可分发给 follower，web 版才接近用户）
3. **核心判断：护城河不在程序在原则的进化**——每次真实使用产生的采纳决策 diff 是方法论持续进化的燃料，程序要留痕这些决策；规则集是"随使用持续生长的活规格"不是静态归纳
4. **分发时序**：作者自用出真实数据 → follower 版本（web、简化原则子集）后置——探路者先行结构
5. **最小闭环排序**：文件级闭环+采纳留痕最先；评估历史与方法论回写随后；分发暂缓

## 引擎完成后的运营重评（2026-09-05，提炼端补上后）

- 产品叙事升级：从"精修工具"到"创作流水线"（写作→提炼创作谈→指导精修→新日志喂回）——可对外讲述
- **journal 价值重估**：连续 journal（39 天）从"记录"升为"资产"——每篇都是提炼素材，写作获得内在回报
- 边际成本近零（单次 2k 字级）→ 可对 follower 免费
- **新风险：产出权威性**——引擎量产的创作谈只靠一次 LLM 调用背书，须标"AI 初稿待作者审定"，审定后才升格正式资产；否则低置信规则稀释体系
- 运营对象转变：从"打磨工具"变为"内容生产线"——原料供给（继续写 journal）+ 出厂质量（审定）+ 铺货（qtfounder 官网）
- **用户反馈校准（重要，2026-09-05 两次实证）**：① 运营评审的产出线（数据资产复利/成本/分发/信任链）用户全不关心，"**我只关心创作谈的叙事质量**"——对作者型用户，内容质量 > 产品运营全套框架；评创作类产品先评文本本身。② 引擎产出被终判"输出结果是一个分析器而不是一个完整的创作谈"后，"太复杂了 通俗点"的简化请求连发——**用户要的始终是"一篇好文章"，所有工程包装（规则集/维度/流水线）都不是目标本身**

## 架构细节

- `laboratory_core`（lib.rs）：领域逻辑统一层；`lab`（CLI）与 `lab-gui`（egui）均为薄壳（只做参数解析/界面，40 行级）
- LLM：复用 `quanttide-agent` crate 0.1.2（不自己写 HTTP）；默认 GLM glm-5.3-flash，`LAB_LLM_PROVIDER=glm/llm/mimo` 切换、`GLM_MODEL` 覆盖；凭据全走 env（GLM_API_KEY 等），**未配置时 CLI 返回 401**
- Cargo：lib `laboratory_core` + 两个 bin（`lab` 必选、`lab-gui` 挂 `gui` feature）；edition 2024

## 与 learning 域的同构

人工示范（探路者做事）→ diff 考古成规格（学习云提炼）→ 程序固化（follower 可执行）——探路者范式的代码域版本。"规格先行"= 方法学是资产、代码是当前快照：docs/ 改了，代码跟着改，验证标准始终是 docs/ 那篇。

## 产品运营评论实例（2026-08-30）

用户拿 revision 功能要求"从产品运营的角度评论"——评论要点（全命中，用户接着给出思路升级）：定位（验证器 vs 产品：单次评估器无作品语境/无采纳界面/无状态/无 diff/无成本透明）、护城河判断（不在 35 行程序在七条原则的持续进化——每次使用的采纳决策是方法论燃料但当前全丢失）、分发时序（作者自用先行，follower web 版后置）。用户随后的思路升级见"实例三"：规则可变、提炼规则的程序不变。
