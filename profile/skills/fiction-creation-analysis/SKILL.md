# 小说创作分析与沉淀

用户（量潮创始人）持续创作网络小说（职场言情 61 篇为创作主体，另校园/重生言情），创作资产在 `quanttide-founder/assets/fiction/`，分析沉淀到 `quanttide-founder/assets/memory/`。任务类：通读正文 → 提炼创作规律 → 沉淀到 memory → 支撑后续创作。

## 仓库结构（**2026-09 已重构：动手前先 ls + 读 fiction/AGENTS.md，勿按本档旧路径找**）

```
一级文件夹 = 一本小说      职场言情（主线）· 校园言情（if 线）· 重生言情
二级文件夹 = 一个阶段      1_母题 → 2_场景 → 3_初稿 → 4_成稿

无编号     = 未排序        等待排序的素材
```

要点（曾误判"11_x 缺口"——实际 11_1 在 3_初稿，是"编号在、阶段未到"）：
- **编号即排序**：无"正式/候选"之分，哪个阶段都有编号（4_改稿 完整排序 / 3_初稿 11_1 / 2_脚本 2_2·6_2·9_1）
- **无编号 = 素材池特征**（等待定位）
- 同名 "2" 后缀 = 同一排序位置的不同版本（7_1_酒吧表白 2）
- 三线阶段命名不同（职场 灵感/脚本 vs 校园 素材/提纲）——照实显示，不统一

## 工作流

1. **通读全文不偷懒**（用户纠正："读全文看情节，不要偷懒"）——读全部章节，不可抽样。文件多时用 execute_code 分批读取（每批 ≤ 40KB 防 stdout 截断），关键文件（创作谈/人物关系）用 read_file 完整读
2. **先读 1_灵感 的创作谈**——作者思路的直接表达（叙事疗法定位、母题选择、情绪→场景机制），是分析的地基
3. **提炼组织规律**：场景序列（关系距离阶梯）/ 信息揭示节奏 / 双线交织 / 物件装置 / 金句落点 / 元叙事 / 主题递进 / 地点=时间坐标
4. **选一个点深入**（用户纠正："这些分析对接下来的创作整合还没有太大帮助，选择一个点深入"）——全景梳理之后必须聚焦一个可操作的点（如缺失章节段、素材转化方法），给出可执行的创作方案，不铺全景
5. **沉淀到 memory**：
   - 情节/规律分析 → `memory/context/<topic>.md`（如 fiction-plot.md）
   - 创作方案/方向 → `memory/roadmap/<topic>.md`（如 fiction.md 的 11_x 方案）
   - **README 只做入口+导航**（用户纠正："不应该写 README，重写"）——内容放独立文档，README 加文档导航表
6. 推送链：memory 子模块 → quanttide-founder 父仓库；**push 前先 pull --rebase**（远端常有他人提交，直接 push 会被拒 fast-forward；commit 前若工作区有未提交修改，先提交再 pull --rebase）

## 核心方法论：素材→正文转化 8 规律

脚本（2_脚本）写"作者想说的道理"，成稿（4_改稿）写"角色演出来的情绪"——本质是**从直述到演出**：

1. **场景先行**：抽象素材 → 具体空间（"海边孤独敲电脑" → 栈道+长椅+月光）
2. **物证化**：情绪必须有物证（"她一直关注他" → 长椅+邮箱窗口+全员信）
3. **减法优先**：删除率 70-80%，删掉道理留下感受
4. **独白→问答**：35 行内心独白 → 一句撞击（"有人心疼过你吗？"——"有啊。我自己。"）
5. **动作外化**：情绪 → 身体（呐喊/拽手腕/衬衫湿）
6. **具象落点**：结尾用画面不用总结句（"三十岁的他们，好像一对二十岁的年轻人"）
7. **悬念保留**：直述 → 对话悬念（"你怎么知道..."）
8. **素材分流**：一个素材拆开分配到最合适位置（父亲手术线 → 家庭线）

完整版见 `memory/context/fiction-adaptation.md`。

## 创作日志轨迹分析方法

读 `草稿箱/1_创作日志/` 时，按时间顺序通读全部日志，提炼**一条主线**（不是逐篇摘要）：

1. 列出每篇日志的核心动作（试了什么方法/遇到什么卡点/有什么发现）
2. 归纳反复出现的模式（如「每到心情好就想写不克制的，每到卡住就回到感受表达」）
3. 找转折点（哪天的认知变化改变了后续方向）
4. 总结为一句线索（如「从技法焦虑→真实表达→找到稳定输送方法」）

## 用户偏好（明确纠正）

- **分析要对创作整合有帮助**：聚焦一个可操作点（缺失章节段/转化方法），而非全景铺开
- **可换角度再深入**：结构角度（情节组织）与方法角度（素材转化）互补，用户会要求"再选一个角度"
- **通读全文**：抽样分析会被纠正
- 沉淀分层：规律→context、方案→roadmap；README 只做导航

## 关联：创作谈引擎（可承接部分提炼工作）

`quanttide-founder/examples/default` 实验室已有 `lab creation-talk <日志...>` CLI（规格 docs/fiction/creation-talk-engine.md）：从创作日志自动提炼创作谈。**创作谈的定义（用户 2026-09-05 拍板，此前引擎方向两次跑偏后纠正）**：

> **创作谈是一篇完整的文章（随笔体），不是分析报告。**

区分标准（这是用户核心质量要求，违反即"输出的是分析器不是创作谈"）：
- ✅ 创作谈：第一人称"我渐渐发现"的叙述；以真实瞬间为骨骼（顿悟/转折/踩坑/告别）；做法和教训融进叙述（"我一开始总想替人物把话说完，后来发现人物自己会开口"）；日志原话尽量保留；读者自己看出母题
- ❌ 分析器（要避免）：分点罗列、"证据：/操作：/展开："标签、母题/风格编号分层、元评论（"素材不足""按保守原则处理""证据链"）、格言式对仗总结（"删掉 X 留下 Y"）、文件分拣说明

**定义已由用户给出并落地（2026-09-05 同日终局——勿再按"定义待给出／实验已冻结"对待）**：用户的定义语 = 「**创作日志 → 程序 → 创作谈**」，并要求 AI 先写下对创作谈的理解（`docs/fiction/creation-talk-reflection.md`）。据该定义，引擎规格与 SYSTEM_PROMPT 已重写为**文章体**（提示词角色"代笔人"；禁列表/标签/元评论/格言总结）并提交推送（commit 6b1d6a0 / 父仓库 9fe5567），**文章体版尚未跑实测**（lab 长文调用挂起缺陷未修）。纪律：AI 不得自行发明文体定义；但用户给出方向语后要立刻据此重写，不要停在"等定义"状态。

引擎与本 skill 的分工：人工分析做引擎做不到的——跨仓库的结构性洞察、选点深入的创作方案。完整演进、文体四轮反复与九条通用教训见 quanttide-repo-workflow 的 `references/creation-talk-engine.md`
