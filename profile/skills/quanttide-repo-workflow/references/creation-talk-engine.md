## 用户思路（一句话，仍有效）

"规则是可以变化的，提炼规则的程序是不变的"——revision 的七条规则内嵌在 SYSTEM_PROMPT 里（规则=代码的一部分），creation-talk-engine 把这个关系倒转：程序是通用提炼引擎，规则集／文章是它的输出产物（文件），不是代码的一部分。

## 流水线设想（未被否，未验证）

```
创作日志 → 【创作谈引擎】→ 创作谈 → 【评估器 revision】→ 建议 → 作者采纳 → 新日志喂回
```

两台程序以产物文件解耦。对齐学习管理：创作日志=journal，创作谈=schedule。

## 规格演进史（全部用户驱动）

1. 初稿 107 行（证据分档矩阵 A/B/C ／ --goal 参数 ／ 产物模板 ／ 排期）→ "太复杂了，怎么简化" → 砍到 23 行。**实验室规格写给作者自己跑——"写代码时才需要的事"不进规格**
2. 追加"正反规则都收"（坑提炼为"别这样做"，负面规则往往更可执行）——用户拍板
3. 追加"母题/风格两维度"（写什么 vs 怎么写）——用户拍板；**文章体版不再分节，两条降为历史**
4. 产出被评"**方向完全偏离了。输出结果是一个分析器而不是一个完整的创作谈**"——分点罗列 + "证据：／操作："标签 + 编号 + 元评论全是分析器文体 → 用户"退回到之前的原始状态"→"也清理"
5. AI 自行按"随笔体／代笔人"重写规格与提示词（未提交）→ "**方向全乱了。丢弃所有和创作谈引擎的代码和文档**" → 整体回退。**AI 提议的定义未经用户确认不算数**
6. **真范本对照**：用户当天在 fiction 仓库亲自提交 `创作谈/` 目录三篇（创作方法/半自传体小说、创作动机/2026 年开篇、人机分工/AI 小说阅读体验）——全是第一人称随笔：有具体的事（公司群吐槽"老派"但代入感十足、按平台分工的投稿策略）、观点藏在叙述里、原话保留（"我发现我其实是在发现故事"）。**这就是"创作谈"的实证定义**
7. **用户给出定义（终局）**：AI 复述偏离后，用户以三词方向语交付定义「创作日志 → 程序 → 创作谈」→ AI 据该方向重写规格首节 + SYSTEM_PROMPT（代笔人）并提交。**等用户给定义 ≠ 原地冻结**

## 教训（写引擎／文体类实验的通用）

1. **产出被否 ≠ 加功能/加模式**——"分析器 vs 创作谈"是文体错误不是功能缺失；先确认要的文体，再动提示词
2. **AI 提议的文体定义未经用户确认时，用户说"退回原始状态"指全部回退**——含自己刚写的未提交版本，不留半成品
3. **实验被否时数据产物一并清理**（用户"也清理"）——AGENTS 临时文件规矩（产物进 data 提交）是通用规矩保留，具体产物随实验命运走
4. **等用户给定义，但别原地冻结**：不被允许发明定义；用户给出方向语后立刻按其重写
5. **范本锚定先核对用户语境（根因）**：接手"产出 X"类任务，第一动作是找**用户自己写的 X 成品**——不要把仓库里名字相近的文档当样板（我把规则手册 fiction-revision.md 当成创作谈范本，真范本当天就在同一仓库里）
6. **跨域纪律不裸搬**：证据链强制／保守输出／冲突保留是从学习管理域搬来的**档案员纪律**——装进创作工具就产出审计报告；每个域有域的灵魂
7. **同类纠偏第二次出现 = 停下交原始样本**：用户两次追加（正反规则／母题风格）被读成"框架对内容补"，实际每次都是分析器加深——应早拿一份未加工产出问"这是你要的形态吗"
8. **文体类产物禁自评**：曾用自造的档案纪律标准给自举产出打"质量超预期"，表扬的恰是后来被否的特征——合格判定权在用户
9. **被指"只关心 X 质量"时立即收敛**：曾两次应"产品运营视角"要求给整条内容生产线的运营分析，用户回"这些我都不关心。我只关心创作谈的叙事质量"——运营／战略框架只说一次，用户圈定质量维度后，回答全部落在该维度内

## 实测记录（方法仍可复用）

- 正向（规则集版）：journal（整合期）→ 四条规则全带证据链；诚实拒绝（日志5 完结告别 →"素材不足"）；反向验证（创作谈喂 revision 正确命中三条）
- 自举三实例：规格自审（revision 判"规格非叙事、无命中不强造"）；产物当素材（引擎吃自己的输出，元认知正确——识别输入全是产品非原始日志）；精修闭环**未跑通**（11KB 长文调 revision 三次挂起 180/300/590s，API 直连通——lab 缺 --timeout／流式，工程缺陷待修；长文用后台跑或分块）
- 跑长文 LLM 实验前先对齐"这轮产出拿去做什么"——曾连跑三轮烧掉近 15 分钟，事后用户不需要第三轮
- 凭据：GLM_API_KEY 从 `~/.hermes/auth.json` 的 `credential_pool.zai`（**数组** `[0]['access_token']`）读出写 /tmp，用完删
