# 案例：qtcloud-think Studio（4D 认知工作室）设计决策链

> 2026-08-22 会话实录——展示设计原则如何在真实迭代中落地。

## 背景

qtcloud-think（思考云）= 思维外脑（人类默认神经网络状态时承载需切换任务正向网络的任务）。认知建模简化为两层（心智模型本体 + 情境意识实例）+ 4D 认知过程（感知→理解→预测→决策/行动）。

## 决策链（含用户纠正）

| 步骤 | 我的初版 | 用户纠正 | 落地 |
|------|---------|---------|------|
| 导航 | 收集/澄清/结构（转译） | "为什么不直接用原始概念" | 导航 = 4D：感知/理解/预测/决策 |
| 第四环 | 决策/行动二选一 | "决策和行动用哪个比较好" | **决策**（认知闭环终点，行动=现实执行越界） |
| 任务命名 | 清晰度判断/本体挂接（名词） | "任务都应该是动作" | 判断清晰度/挂接本体→动词+名词 |
| 预测任务 | 挂接本体/升级模式（结构组织） | "预测的任务不太对" | 识别模式/推演走向（从现状推未来） |
| 对照本体 | 我发明"推演与本体对照" | "对照本体是什么？"→说不清 | **移除**（语义诚实） |
| 两层建模落地 | 本体树呈现/实例挂接/升级 | 需求地图无对应任务 | 全部移除（需求地图是法源） |
| 实施策略 | 四端齐做 | 无 | 验证先行：最小闭环（感知+理解）→真实使用→预测/决策延迟 |

## 页面功能（最终定稿）

- **感知页**：想法输入（零门槛不打断）+ 想法流时间线 + 导入素材（quanttide journal）
- **理解页**：判断清晰度 → 澄清想法（多轮）→ 加工结构化（事实/感受/行动，用户确认）→ 加工完成即情境意识实例（无独立"升级"动作）
- **预测页**：识别模式 → 推演走向（趋势+分支）
- **决策页**：确立目标（从推演走向中选择，AI 候选+用户确认）→ 记录决策（时间线+实例关联）

## 结构演进（repos/ 惯例对齐）

`data/`（✗ 非 DDD 名）→ `domain/+infrastructure/`（✗ 过度分层）→ `models/ + repositories/ + screens/`（✓ 对齐 qtcloud-agent 三件套）

- 仓储 = ThoughtRepository（DDD Repository 模式——接口封装数据访问）
- 种子数据 assets/data（git 跟踪）vs 用户数据 ~/.qtcloud-think（忽略）——存储位置非仓储概念
- 失败降级设计：AI 失败 → 抛明确错误，不造假结果

## 测试设计模式

- 模型单测：JSON 往返/状态流转合法/默认值
- 仓储单测：临时目录注入（Directory.systemTemp.createTemp()）/MockClient/失败路径必测
- widget 测试：依赖注入假仓储（InMemoryThoughtRepository），screens 构造接收仓储
- 分两步实施：先单元测试部分（models+repositories，16 测试全绿），后组件测试部分（screens+导航）
