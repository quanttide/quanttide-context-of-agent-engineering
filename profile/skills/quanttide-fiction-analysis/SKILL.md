## 仓库结构（**结构演化快——动手前先 ls 目录 + 读 fiction/AGENTS.md，勿按本档记忆找路径**）

```
fiction/
├── 职场言情/ 校园言情/ 重生言情/   # 一级文件夹 = 一本小说
│   ├── {N}_{阶段}/  # 创作阶段——⚠️ 阶段名各小说不同，动态发现不硬编码（见下）
│   └── index.md     # 晋江发文资料（标题/一句话简介/标签/立意）
├── 观察站/          # 跨系列共用观察素材（2026-09-26 起，取代草稿箱）
│   ├── 1_情绪日记/  # 以情绪为单位——母题的发现来源
│   └── 2_社会观察/  # 社会观察素材
├── 实验室/          # 实验设计与结果（README.md 为实验设计，结果直接写本目录）——AI 产物，与观察站（人类素材）分开
├── 创作谈/          # 作者亲自写的创作谈随笔（README + 创作动机/创作方法/人机分工）——**文体范本**
├── CHANGELOG.md     # 含创作契约版本（motif/story/style.yaml 母题契约）
└── myst.yml         # MyST 文档站配置
```

**阶段目录动态发现（2026-09-26 实测）**：各小说阶段名不同，不能按统一四段找——职场言情 = `1_灵感/2_场景/3_初稿/4_改稿/5_定稿`，校园言情 = `1_素材/2_提纲/3_初稿/4_改稿`（另有 `4_改稿/番外1_*`），重生言情 = `1_灵感/2_场景/3_初稿/4_成稿`。按 `{N}_{名称}` 模式识别阶段即可（toolkit `fiction_engine.dart` 的 `Stage.discover` 即此实现）。章节文件 `{序号}_{标题}.md`，序号可省（未编号=替代草稿），`0_` 前缀=非正文，预留空号宁空勿移。

**素材流向（AGENTS.md 2026-09-26 版）**：情绪日记（`观察站/1_情绪日记`）中发现母题 → 归入各小说 `1_灵感`（校园为 `1_素材`）；**创作日志/创作谈/创作设定已迁至 `assets/memory` 的 `write/` 记忆集**，fiction 不再存放。

**已废弃路径（勿按旧记忆找）**：小说内 `0_日志/`、`2_脚本/`；`草稿箱/`（→`观察站/`，且 3_创作谈/4_创作设定 迁 memory）；统一四段式 `1_母题/4_成稿`（阶段名已各小说分化）。

**资产结构规则（用户明确，仍有效）**：一级文件夹=一本小说，二级文件夹=一个阶段，文件编号=排序，无编号=未排序（"2"后缀=同排序位置另一版本）。章节编号 = 场景单元（咖啡厅重逢/展会再遇/便利店谈心/海边散步/酒吧表白/好友聚餐）。

## 作者创作方法论（2026-08-09 分析沉淀，稳定特征）

1. **叙事疗法定位**：小说是"叙事重构平台"——把现实情绪（不敢说的）放进故事框架重新驱动。"把不敢说的，变成可以说的"
2. **情绪驱动场景**：章节 = 情绪场景单元；情绪与环境可**相反**（环境热闹氛围反而文艺）；从情绪日记出发重构
3. **母题与悬念**：双向暗恋久别重逢母题（集体潜意识载体），**刻意回避破镜重圆**（小众分支）→ 要求合理动机 → 构成最大悬念
4. **半自传体继承**：男女主 = 作者意志的继承者；职场情节 = 真实工作体悟（"三天迭代八个产品"→"三天更新八个子系统"），可加工发公司账号（小说即品牌故事）
5. **意象系统**：海边 = 十年前，公园 = 十年后；雨母题（酒吧场景）；"瓶子"（赏雪谈心原型）；"渴望被看见"反复出现
6. **人物自然涌现**：反预设——让人物自然出现再去解释梳理（"两桌人终于坐上了一桌"）
7. **关系公式**：男主几乎与世隔绝，女主闯入 → 压抑的孤独和渴望喷涌而出；"理智落后于情感，不断突破边界"
8. **多世界互文**：校园言情 = 职场言情 if 线（同一对男女主）；未来复用形象写重生
9. **"墙"的隐喻**（创作谈2）：写作 = 面对无形阻碍，墙写出来就知道是什么；创作瓶颈本身可成为创作源泉

## 分析框架

母题选择 → 悬念引擎（设定张力）→ 情绪场景组织 → 意象系统 → 人物涌现方式 → 多世界互文 → 现实隐喻层。

## 情节组织分析：必须读全文（用户纠正："读全文看情节，不要偷懒"）

分析情节组织时**不能抽样**——19 个改稿章节全部通读后再总结。章节按编号排序读（1_1→12_3 即时间顺序）。用 execute_code 分批读（每批 6-7 个文件，避免上下文溢出），不要只挑代表性章节。

### 正文组织框架（2026-08-14 全文分析沉淀）

1. **场景序列 = 关系距离阶梯**：每章一个"关系事件"（无过渡章节），推进一个距离刻度（物理接近→心理接近→空间主权→关系确认→社会公开→家族/终极）
2. **信息揭示四层节奏**：读者已知（日记/消息）→ 旁观者确认（配角吃瓜）→ 互相揭示（历史守望）→ 补全升华（真相/信）——"谁不知道什么"驱动张力
3. **双线交织**：浪漫线（关系进展）× 治愈线（各自创伤暴露），每章对话既推进关系又暴露创伤；转折章 = 治愈从单向变双向
4. **物件装置**：贯穿道具呼应（行李箱→拖鞋/毛巾→眼罩/相册→19岁信）——记忆的实体化
5. **配角 = 信息装置 + 质感来源**（牵线者/吃瓜者/餐馆老板）
6. **金句 = 情绪高点**：每章一个高点句收束情绪
7. **元叙事入文**：作者的设计思想/哲学直接由角色说出（if 线讨论/三堵墙/千年远见）
8. **主题递进线**：渴望被看见 → 互相看见 → 互相治愈 → 共同面对 → 超越时间
9. **地点 = 时间坐标**：每个场景地点有"十年对应物"（海边=昔守望/公园=今拥抱）

### 素材→正文的转化规律（2026-08-14 脚本版 vs 成稿版对比提炼）

同章节的 `2_脚本/`（脚本版）与 `4_改稿/`（成稿版）对比可提炼转化规律（样本：6_2 海边散步、7_2 公园拥抱）。核心认知：**脚本写的是"作者想说的道理"，成稿写的是"角色演出来的情绪"——从直述到演出**。8 条规律：

1. **场景先行**：抽象素材 → 具体空间（场景是情绪的容器；脚本没场景，成稿必有）
2. **物证化**：情绪必须有物证（"她关注他" → 长椅+邮箱窗口+全员信）
3. **减法优先**：删除率 70-80%，删掉道理留下感受（35 行独白 → 成稿几乎全删）
4. **独白→问答**（最核心）：千言万语压缩成一句互相撞击的问答（"有人心疼过你吗？"——"有啊。我自己。"）
5. **动作外化**：情绪 → 身体（呐喊/拽手腕/衬衫湿/头埋深）
6. **具象落点**：结尾从道理 → 画面（"并肩而行" → "三十岁的他们，好像一对二十岁的年轻人"）
7. **悬念保留**：直述 → 对话悬念（"你怎么知道..."）
8. **素材分流**：一个素材拆开分配到最合适位置（7_2 版本2 的父亲线挪去家庭线）

应用清单（把 2_脚本 素材变成正文时）：找场景 → 找物证 → 删 70% 对话 → 道理变问答 → 情绪外化动作 → 结尾用画面。

## 分析要有操作价值（用户纠正："这些分析对接下来的创作整合还没有太大帮助，选择一个点深入"）

全景分析（情节组织/创作方法论）是基础，但**对"接下来写什么"要有可操作产出**——从全景收敛到一个点深入：

- 找创作缺口（如改稿编号缺失段 11_x）→ 诊断为什么缺 → 给章节方案（功能/素材映射/情绪落点/呼应装置）
- 破卡点优先用**已存在的世界/素材**（论坛/包子店/便利店），不新增群像人物
- 产出落点分工：**写什么**（章节方案）→ memory `roadmap/fiction.md`；**怎么写**（方法论）→ memory `context/`（roadmap=方向层，context=方法层）

## 不代笔正文：续写请求给判据与节拍，不给成稿（2026-09-05 实证）

用户问"这一章怎么继续写下去"时，我写了两版 `4_专访.md` 续写（第一版用桌面对话推进剧情，第二版推翻重写为物证+动作版），两版都被否："**写的很空洞**" → "**写的不好。不要继续写了**"。

- **空洞的根因是让角色把主题念出来**：把 `1_母题/男主原型.md` 里"能改变的其实不多""心态上的弯路"直接写成台词。这同时违反作者自己的转化规律（物证化 / 减法优先 70-80% / 独白→问答 / 动作外化 / 结尾用画面）和精修七条（删除创作说明、弱化断言、具体优先）——**作者已把自己的手法写成文档，代笔前先按那两份文档自检**
- **功能性对话 ≠ 小说的写法**：作者的章节是内心独白 + 物证 + 短句留白，情节几乎不动而情绪全在。写成"她说 X 他说 Y"的推剧情对话，方向就已经错了
- **正确交付形态**（三件）：① 类属判断 + **可验收的判据**（如"确认现在"型的判据：若后续走向是"用预知规避某个具体遗憾/换取具体好处"则该读法为假；若走向是"想改点什么最后发现值得留住的不是结果而是当时的人"则成立）② 节拍设计（本章要完成哪几件事、每个道具承担什么功能）③ 必要时给一两句示范句，不给成段正文
- **正文由作者执笔**：这是他的私人创作空间（见下文"不要擅自修改创作内容"）。AI 的价值在判据、结构与节拍；代笔出不来的东西不要硬写，被否两次后用户会直接叫停
- 被否后的正确反应：停手、如实说"文件没动"，不要立刻再交第三版

## 分析沉淀

分析结果写入 `assets/memory/context/`（quanttide-memory-of-founder 子模块）：
- `fiction.md` = 单场戏/人物弧光分析
- `fiction-plot.md` = 全文情节组织分析（2026-08-14 已沉淀，含 19 章节情节线 + 上述框架）
- 沉淀位置分层（2026-08-15 定）：**intention/** = 意图/规划（如"作者对平台的规划"= 自我操作系统，文件 `qtfounder.md`）；**roadmap/** = 方向（写什么/章节方案）；**context/** = 方法（怎么写/转化规律）；分析类（情节/弧光）= context。intention 目录需按需新建（memory 原无此目录）
- 提交链：memory 子模块 commit+push → quanttide-founder 父仓库更新指针；**memory 远端常分叉**（其他 agent 也在写），push 失败先 fetch + rebase 再推

## 仓库操作陷阱

- **分离头常见**：子模块常处于 detached HEAD——先 `git checkout main` 再操作
- **分支分叉**：本地与远端可能各自有同一章节的不同版本（8_2_好友聚餐 曾分叉）——合并前先向用户确认以哪边为准（本次用户选"以远端为准"，Fast-forward 合并无冲突）
- fiction 是**用户私人创作空间**：分析要准确、尊重；不要擅自修改创作内容

## 关联

- fiction 是 quanttide-founder 仓库的资产子模块（apps/qtfounder 应用 + archive/fiction/memory 资产）；git 操作规范见 `quanttide-git-ops`
