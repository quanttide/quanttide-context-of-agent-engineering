# 用户故事地图撰写标准（product-requirement）

权威来源：`data/profile/.agents/skills/product-requirement/SKILL.md`（profile 仓库内，三段论：目标/流程/验收标准）。本文件为 Hermes 侧摘要，写/审查 requirement.md 时应用。

## 目标

撰写一份可信赖的产品用户故事地图：以用户视角刻画产品需求，让所有人看到同一张产品地图。

## 流程（五步）

1. **用户画像**：一行 `用户画像：需要…的[角色]`
2. **活动**：按用户旅程时间顺序划分（不是系统模块）；每活动含活动名 + **活动描述段**（一段话说明流程/目标/价值）+ 任务列表
3. **任务**：`### 任务：[动词+名词]`，一句话概括（不展开细节）
4. **故事**：`· 用户要[动作]，[目的/价值]`，展开任务细节；**一条故事 = 一个可独立交付的用户价值**（不是系统功能点，也不是"管理整个XX"）
5. **评审**：按验收标准逐条检查，修正不合格故事

## 验收标准

### 必须满足
- [ ] 每个活动都有描述段
- [ ] 所有故事都是"用户要…"句式（无系统动作混入）
- [ ] 活动按用户旅程时间顺序（不是系统架构顺序）
- [ ] **主线故事清晰**——读完能理解"这个产品帮用户解决了什么问题"
- [ ] 故事符合目标用户视角（不是开发者/系统视角）

### 质量检查
- [ ] 故事颗粒度一致
- [ ] 无功能清单式描述（"支持XX"不是故事）
- [ ] 用户画像一行完成

### 反模式

| 问题 | 示例 | 修正 |
|------|------|------|
| 系统动作 | "系统要记录部署状态" | "用户要记录部署状态…" |
| 功能清单 | "支持多租户" | "用户要按租户隔离数据…" |
| 模块当活动 | "活动：认证模块" | "活动：用户登录" |
| 缺描述段 | 直接列任务 | 先写活动流程说明 |
| 颗粒度过大/过细 | "管理整个系统"/"点击保存按钮" | 统一在"用户要XX"粒度 |

## 优先级标注

**故事地图不标 P0/P1**：地图刻画需求（是什么），版本规划（先做什么）在迭代阶段确定。需求完整比优先级标注更重要。
