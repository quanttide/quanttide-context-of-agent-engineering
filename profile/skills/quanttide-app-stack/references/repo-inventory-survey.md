# 存量件盘点：哪些可以删 / 归档 / 迁出

来源：2026-09-24 qtdata `src/studio` 实录（提的三个「可以删」候选被用户三个全否）。配合 `status-doc-refresh.md`（体检与三件套）一起用。

## 一、产出形态：候选 + 在用证据 + 裁决去向，不是删除建议

用户问「哪些文档/代码/测试已经过时，可以考虑删除或归档；哪些不适合继续在这个文件夹维护」时，要交的是**一份可裁决清单**，每条四样：对象 / 规模（跟踪文件数、行数）/ **用没在用上的证据** / 建议去向（删 · 归档 · 迁出 · 完善），然后等裁决。

**实测：三项「可以删」被三项全否。**

| 我的候选 | 理由（我给的） | 用户裁决 |
|---|---|---|
| 四个平台目录 android/ios/macos/windows（105 个文件） | 产品只发 Web，这四个从未构建 | **保留，且需要完善** |
| `integration_test/`（空目录） | 无用例，E2E 在仓库根 `tests/` | **也不完善，需要维护** |
| `doc/`（两页 HTML 原型 9 个文件） | Flutter 之前的旧物，现行原型在 `docs/dev-guide/` | **是分解过的，不能删** |

判死三个错三个——**「看起来像脚手架垃圾」在这个仓库里多半是有意保留或待完善的**。所以：候选里凡是「删」的，写完先自问能不能给出反证（谁在用它、谁依赖它），给不出就把去向降级成「保留 + 待完善/待补判据」，把删除留给用户拍。

## 二、判据：找「在用」的证据，不找「没用」的感觉

| 候选类别 | 证据来源 | qtdata 实测 |
|---|---|---|
| 平台目录 | `ls .github/workflows/`（CI 构建哪个平台）+ `ls scripts/`（本地脚本构建哪个） | CI 只 `flutter build web`；`scripts/run-studio-linux.sh` 跑 `flutter build linux` → **linux/ 是现役本地调试形态**；另四个「未构建验证」= 待完善，不是该死 |
| 空目录 | `find <组件> -type d -empty` + 对照 `pubspec.yaml` / `package.json` 的依赖声明 | `integration_test/` 空，但 `integration_test` 依赖已声明 = **声明了意图没落地**，属待补 |
| 原型 / 设计件 | 看文件名与内容结构：有没有区块说明、交互、数据三节（= 页面分解产物） | `doc/index.md` 正是「定位 / 布局 / 区块说明 / 交互 / 数据与文件 / 维护」——**分解产物**，不是可丢的草稿 |
| 死代码 | 逐文件数引用：谁 import 它（脚本遍历 import 行） | lib 21 件全部被引用 → 没有死件 |
| 孤儿测试 | 测试文件 ↔ lib 文件对表；再核对高风险件是否被间接覆盖 | 21 个 `testWidgets` 全部对着现存部件；5 个 Tab 由详情页测试覆盖（渲染 5 Tab / 切 Tab / 弹窗 / toast）；但 `test/helpers/seed.dart` **硬读 seed JSON** = 与数据源耦合，换数据源时 11 个测试会一起坏 |
| 过时命名残留 | `grep -rn "<旧名词>" lib test` | 「仪表盘」还有 3 处（2 处注释 + 1 处用例名）；**CHANGELOG 里的历史记录不动** |

## 三、取证命令

```bash
git ls-files src/<组件> | awk -F/ '{print $3}' | sort | uniq -c | sort -rn   # 按目录看跟踪文件数（「占了多少」）
find src/<组件> -type d -empty -not -path "*/build/*"                         # 空目录
find lib -name "*.dart" -exec wc -l {} + | sort -rn | head -8               # 规模与最长文件
grep -rn "旧名词" src/<组件>/lib src/<组件>/test                              # 过时命名（历史文档别动）
```

死代码与孤儿测试用脚本算（`execute_code` 遍历 `import`，见上文对表法），别靠眼睛扫。

## 四、过时命名的处置要分两类

- **现行代码/测试里的** → 该改（「仪表盘」→「总览」，3 处；注释与用例名一起）
- **CHANGELOG 里的** → 不动，那是历史
- 文件与类名跟着一起改（`dashboard_screen.dart` 与 Tab「总览」不符）——但**没工具链时不要动**（见下）

## 五、没工具链时：能改的改，不能验证的落成待办

没装 Flutter/Go 等工具链时：

- **可以直接改**：注释、文档、测试用例名里的过时词
- **不要做**：文件/类重命名、加严 lint 规则、增删依赖——都要 `flutter analyze && flutter test` / `go vet` 才收得了尾
- **落法**：写进 TODO 的一条（「改什么／判据（可跑的）／影响哪些文件」），文档里如实标「未复跑」

## 六、裁决要写回文档，不是口头接受

用户否掉/保留/改判之后，把新判定写回三件套：

- 裁决「保留且需要完善」→ STATUS 规模表补一行（对象 + 规模 + 现役/待完善）、TODO 新增一段（带可跑判据）、ROADMAP 加分段与欠账项
- 实测：裁决后同步改 STATUS（3 处）、TODO（新增「六段 · 平台与集成测试」+ 一条文件改名）、ROADMAP（新增六段 + 欠账改写），`git status` 里**零删除**——汇报时点明「没有删任何文件」能让用户放心
- 顺手指出**规格层面的缺口**：qtdata 的平台契约只写了 Studio = Flutter Web，桌面/移动端一个字没有——「完善多端」这一件**没有验收判据**，而没有判据的段永远验收不了。这种缺口值得连同裁决一起报告
